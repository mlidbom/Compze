Tessaging

Tessaging is Compze's messaging. Code that has something done, or that tells the rest of the system what happened, sends a message, and the handlers that should receive it do, without the sender and the handlers knowing about each other. What sets Tessaging apart is that a message's .NET type is its whole contract: Compze calls such a type-routed message a tessage.

  • No routing configuration. There are no topic names, queue names or routing keys. A tessage goes to the handlers of its type, and a subscriber to IAccountTevent receives every tevent whose type implements IAccountTevent, including kinds of tevent added long after the subscriber was written.
  • The type declares the guarantees. Whether a tessage may leave its process, and whether its delivery is best-effort or exactly-once, is declared by the interfaces its type implements: neither the sender nor the receiver configures it.
  • One model, from one process to many. The same handler declarations run in a single process's container and in endpoints that converse across processes. Moving a handler to another process is a change of deployment, and the guarantees its tessages declare move with it.
Note

Compze's packages are pre-release: their APIs still change from one version to the next.

The tessage kinds

Kind It says Who handles it
tevent Something happened. Every handler subscribed to a compatible type: none, one or many.
tommand Do this. Exactly one handler.
tuery Answer this. Exactly one handler, which changes nothing.

Two ways to converse

Tessaging carries two communication styles:

  • TessageBus: tell, and trust that it arrives. Code publishes tevents and sends tommands, and doesn't wait for the handlers in other endpoints to run. These pages cover the TessageBus, and what the two styles share.
  • Typermedia: ask, and get the answer now. Tueries and typermedia tommands are executed like requests to a browsable API: see Typermedia.

A first taste

A container composes the LocalTessagingEngine with a handler for each tevent type it cares about:

IContainerBuilder containerBuilder = new MicrosoftContainerBuilder();
containerBuilder.Registrar
                .Register(Singleton.For<AccountStatistics>().CreatedBy(() => new AccountStatistics()),
                          Singleton.For<AccountRegistration>().CreatedBy((IIndependentTeventPublisher publisher) => new AccountRegistration(publisher)))
                .LocalTessagingEngine(engine => engine
                   .RegisterTessageBusHandlers(handle => handle
                      .ForTevent((IAccountRegistered registered) => Console.WriteLine($"Welcome, {registered.Email}!"))
                      .ForTevent((IAccountTevent tevent, AccountStatistics statistics) => statistics.Record(tevent))));

await using var container = containerBuilder.Build();

Publishing a tevent runs every handler whose type it is compatible with:

var registration = container.RootResolver.Resolve<AccountRegistration>();
var accountId = registration.Register("ada@example.com"); //Prints "Welcome, ada@example.com!" before it returns.

All notable changes to Compze.Teventive will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/).

## 0.7.0-alpha

- **Changed without a signature changing, so no compiler error points at it:**
  - **A taggregate's tevents are no longer delivered to other processes unless their hierarchy says so.** `ITaggregateTevent` no longer extends `IExactlyOnceTevent`, so a hierarchy whose root interface declares no delivery guarantee of its own is published and handled within the process only. Nothing fails where it is published: another endpoint that handled or observed its tevents simply receives none. A hierarchy whose tevents other processes need declares its guarantee on its root interface, such as `IExactlyOnceTevent`. Below, under `ITaggregateTevent`.
  - **A taggregate store's updater needs a unit of work that `ExecuteUnitOfWork` began,** and **a publish that fails rolls its unit of work back, even when the code that published catches the exception.** Both are new for a tevent store's taggregates: see Compze.Teventive.TeventStore's changelog.
- **Every teventive class changes: it declares its tevent routing once, for the class,** a taggregate's, its components', its entities' and a shared tomponent's alike, in a `TeventRouting` kept in a static field, and returns it from its override of the protected abstract `TeventAppliers` (and, for a taggregate's tevent handlers, of the protected virtual `TeventHandlers`): `protected override TeventRouting TeventAppliers => Appliers;`. This replaces registering appliers and handlers in every instance's constructor (`RegisterTeventAppliers()`, `RegisterTeventHandlers()`), so an instance holds none of its routing. A class's routing starts with its Compze base class's `DeclareAppliers`, a subclass's extends its base class's with `Extend`, and a tevent reaches the routes it matches one after another, in the order declared, a base class's before a subclass's, as it reached registered appliers and handlers in the order registered. A class that inherits its base class's routing without declaring its own is refused when it is constructed. A taggregate's tevent handlers are declared with `DeclareHandlers`. The constructors no longer take a `TeventDispatcherConfig`. `Taggregate` is abstract. `TeventApplyingRoot<TRoot, TTevent>` and `TeventApplyingPart<TPart, TPartTevent>` are the base classes that apply tevents by a class's routing: the first of a taggregate and of a self-generating query model, the second of their components and entities.
- **Taggregate stores share one programming model:** `ITaggregateStoreReader` (`Get`, `TryGet`, `Reference`) reads the taggregates of whichever store keeps each class, and returns a unit of work's own instance inside it; `ITaggregateStoreUpdater` (`GetForUpdate`, `TryGetForUpdate`, and `Add` for a new taggregate) changes them, one for each unit of work, which must be one that `ExecuteUnitOfWork` began, and which rolls back when a publish has failed, even if the code that published caught the exception; `ITaggregateReference<TTaggregate>` is what code holds across units of work, and only reads: a unit of work gets the taggregate it stands for for update by its `Id`. Compze.Teventive.MemoryImageStateStore and Compze.Teventive.TeventStore both implement them, so one unit of work can change taggregates of both. Asking for a taggregate that no store holds throws an `ArgumentOutOfRangeException`, and asking for one as another class than its own, of the same store, throws. What a read or a get for update costs is each store's own, and its documentation says it.
- **A taggregate is deleted by publishing a tevent that implements `ITaggregateDeletedTevent`,** from a method of its own, as any other change is made; the stores have no delete operation. Inside the unit of work it is then no longer found, by `Get`, `TryGet`, `GetForUpdate` or `ReferencesToAll`, and when the unit of work commits it leaves its store. A taggregate publishes nothing after its deleted tevent: such a publish throws, naming the taggregate and the tevent, and the unit of work rolls back.
- **`ITaggregateStoreBulkReader`,** which extends `ITaggregateStoreReader` with `ReferencesToAll<TTaggregate>()`: a reference to every taggregate of a class, in no particular order, whichever store keeps the class, and inside a unit of work its own view. Reading every taggregate of a class is a scan of all a store holds for most stores, so it has a reader of its own, and code that reads everything says so in what it depends on.
- **`ISnapshotable<TSelf, TSnapshot>`:** a taggregate whose whole state is taken as a snapshot and restored from one, for a store that keeps taggregates as their state. `Taggregate`'s protected `RestoreIdentity` gives an instance being restored its id, and an entity collection's `AddWhileRestoring(id)` adds a restored entity without a tevent, only while the restore lasts.
- A taggregate instance that a store serves to readers is read only: publishing on it throws, saying so.
- **`SnapshotRoundTrip.DifferencesBetweenItAndItsCopy`,** for a consumer's specifications and tools: it makes a copy of a taggregate through a snapshot, as a state store makes each unit of work's copy, and names each difference between the copy and the taggregate, none when the copy holds the state the taggregate holds, in every field of the taggregate's own classes and of its parts. It catches a field the snapshot type has no place for, and one that `TakeSnapshot` or `RestoreFrom` leaves out. A value created on its first read, a `LazyCE` or a `Lazy<T>`, is compared by its value. A specification asserts that the list is empty, and a tool that checks many taggregates reports what it finds.
- **`ITaggregateTevent` is a plain `ITevent`:** it no longer extends `IExactlyOnceTevent`, so a taggregate's tevents are published and handled synchronously within the process, and carry no identity. A hierarchy that a tevent store keeps declares `ITaggregateTeventWithIdentity` on its root interface and derives its root class from `TaggregateTeventWithIdentity`; one whose tevents are delivered to other processes declares its guarantee, such as `IExactlyOnceTevent`. `TaggregateTevent` no longer has an `Id`.
- **`IMutableTaggregateTevent` and `IMutableTaggregateTeventWithIdentity` are internal:** their members, for Compze's internal use, set the values a taggregate gives a tevent when it publishes it, and a tevent store when it reads it back.
- `TaggregateIdentifyingTevent.WrapIn` has an overload for a tevent with identity, returning the wrapped form a tevent migration hands to the tevent store.
- **A `SharedTomponentSlot` belongs to the owner's class:** declared once, in a static field, and shared by every instance, it takes the adopting wrapper tevent implementation and a `Func<TOwner, SharedTomponent<TTomponentTevent>>` that gets the shared tomponent from an owner, and a shared tomponent is constructed with `slot.In(owner)`. The owner keeps no slot object.
- **A `SharedTomponentSlot` refuses an adopting wrapper tevent implementation that doesn't implement its adopting wrapper tevent:** constructing it with another slot's wrapper, such as the billing address's for the shipping address, throws an `ArgumentException` naming the implementation. Before, the slot's tevents were wrapped as the other slot's and applied to that slot's tomponent, with no error.
- **Requires newer minor versions of other Compze packages:** Compze.DependencyInjection 0.10.0-alpha (was 0.9.0-alpha), Compze.Internals.SystemCE 0.9.0-internal (was 0.8.0-internal). Upgrading to this version upgrades each package listed here too, so their changelogs apply to this upgrade as well.

## 0.6.0-alpha

- **Targets .NET 11 (`net11.0`) instead of .NET 10, and is compiled with runtime async:** the runtime, instead of state machines the compiler generates, suspends and resumes its async methods, so live stack traces show the real call chain. An application that uses this version must target .NET 11.
- **Requires newer minor versions of other Compze packages:** Compze.Abstractions 0.4.0-alpha (was 0.3.0-alpha), Compze.DependencyInjection 0.9.0-alpha (was 0.8.0-alpha), Compze.Internals.SystemCE 0.8.0-internal (was 0.7.0-internal), Compze.Tessaging.Abstractions 0.6.0-alpha (was 0.5.0-alpha), Compze.Threading 0.12.0-alpha (was 0.11.0-alpha), Compze.TypeIdentifiers 0.3.0-alpha (was 0.2.0-alpha). Upgrading to this version upgrades each package listed here too, so their changelogs apply to this upgrade as well.

## 0.5.1-alpha

- **`IMutableTeventDispatcher` and `ITeventSubscriber` are safe to use from several threads at once:** to dispatch, to register handlers and to dispose subscribers. Before, two dispatches on different threads could corrupt the dispatcher's cache of the handlers each tevent type routes to ("Operations that change non-concurrent collections must have exclusive access"), and a registration or disposal racing a dispatch could corrupt its lists of subscriptions. Handlers still run synchronously on the dispatching thread, outside the dispatcher's lock; each dispatch calls the handlers subscribed when it began. A dispatch of a tevent whose type the dispatcher has already resolved takes no lock at all, and is as fast as before.
- `IMutableTeventDispatcher.Handles` no longer lets a later `Dispatch` of a tevent nothing handles pass silently: asking about such a tevent cached an empty list of handlers for its type, and the dispatch then skipped the `TeventUnhandledException` check.
- **Requires newer minor versions of other Compze packages:** Compze.Internals.SystemCE 0.7.0-internal (was 0.4.0-internal), Compze.Threading 0.11.0-alpha (was 0.9.0-alpha). Upgrading to this version upgrades each package listed here too, so their changelogs apply to this upgrade as well.

## 0.5.0-alpha

- **`PublisherTevent`, `PublisherTevent<TTevent>` and `WrapTevent` leave for `Compze.Tessaging.Abstractions`.** Every tevent is wrapped before routing, which makes the wrapper a tessaging routing concept rather than a Teventive one — and they already declared a namespace neither the assembly holding them nor the concept routing them pointed at.
- `TeventDispatcherOptions` is dissolved: a single-flag enum said less than the `IgnoreUnhandled` overloads that now say it directly, including the three- and four-type forms.
- `AllowPublicSettersAttribute` is deleted, and the unreferenced `Email`/`Password` value types with it.
- The visibility sweep reaches this package: non-public machinery moves below `_internal`/`_private` namespace sections — the markers that replaced the old `Internal`/`Private` spelling — and types and members are narrowed to the least visibility that compiles.

## 0.4.0-alpha

- Added shared tomponents and tentities: `SharedTomponent`, `SharedTentity`, `SharedTentityCollection`, and `SharedTomponentSlot` - reusable teventive components and entities that any taggregate can own, rather than being nested in one specific taggregate's tevent hierarchy. A shared teventive's tevents are bare `ITevent`s rooted in its own hierarchy; the owner declares, per member slot, an adopting wrapper tevent (an owner tevent that is also an `IPublisherIdentifyingTevent<T>` of the shared teventive's tevents), and the slot wraps every published tevent in it and routes adopted tevents back to the shared teventive's appliers - during live publishing and history replay alike. Two same-typed members (a shipping and a billing address) are told apart by their slots' adopting wrapper types; individual tentities in a collection by the `ISharedTentityTevent<TTentityId>.EntityId` their tevents carry.
- The close-the-wrapper-type-over-the-runtime-tevent-type mechanism has one home: `PublisherIdentifyingTevent.WrapIn` - taggregates wrapping in their declared wrapper implementations and shared-tomponent slots wrapping in their adopting wrapper tevents both close their wrapper type there. `TaggregateIdentifyingTevent.WrapIn` now delegates to it.
- The dispatcher now routes exclusively by the outer (wrapper) tevent type: every tevent is wrapped in an `IPublisherIdentifyingTevent<TTevent>` before routing, a subscription to an inner tevent type is a subscription to `IPublisherIdentifyingTevent<TheInnerTeventType>`, and the wrapper is opened only at delivery to inner-typed handlers. Handlers subscribed to a type the wrapper itself satisfied (such as `ITevent`) previously received the wrapper; they now receive the inner tevent like every other inner-typed subscription.
- A tevent published without a publisher-identifying wrapper is wrapped in `PublisherIdentifyingTevent<TTevent>` closed over its runtime type. The reflection-emit `WrapperTeventImplementationGenerator` is deleted: no runtime-generated tevent type may ever be sent or persisted.
- `PublisherIdentifyingTevent<TTevent>` moved from `Compze.Teventive.Taggregates.Tevents.Public` to `Compze.Teventive.Tevents.Public` - the root wrapper is a teventive-core concept, not a taggregate one - and its type parameter is renamed `TTeventInterface` -> `TTevent` since auto-wrapping closes it over concrete tevent types. The `PublisherTypeIdentifyingTevent` static helper it replaces is deleted.
- `IMutableTeventDispatcher.Handles` now answers for the same type key `Dispatch` uses, so wrapper-typed (`ForWrapped`) subscriptions are counted; previously it keyed on the raw tevent type and under-reported them.
- `BeforeHandlers`/`AfterHandlers` subscriptions now validate their subscription type like every other subscription and match per-type: a before/after handler typed narrower than the dispatched tevent filters instead of throwing `InvalidCastException`.
- Renamed `Taggregate.WrapEvent` -> `WrapTevent` and `Taggregate.WrapperTEventImplementation` -> `WrapperTeventImplementation`; file names `ITaggregateTypeIdentifyingTevent.cs` -> `ITaggregateIdentifyingTevent.cs` and `TaggregateWrapperTevent.cs` -> `TaggregateIdentifyingTevent.cs` now match the types they declare.
- `ITaggregate` now hands wrapped tevents out of every surface: `Commit` and `TeventStream` deliver exactly the wrapped instances publishing created, and `LoadFromHistory` takes the persisted wrapped tevents and applies the stored wrapper - after a migration has rewritten history, the stored wrapper is the truth, not what the taggregate would wrap today. `ITaggregate<TTevent>.TeventStream` gains precision: `IObservable<ITaggregateIdentifyingTevent<TTevent>>`.
- Extracted the taggregate's wrapping mechanism into `TaggregateIdentifyingTevent.WrapIn(wrapperTeventImplementation, tevent)` so a tevent migration author can wrap a replacement tevent in the publisher's wrapper.
- The routing model's one translation rule has one home: `PublisherIdentifyingTevent.WrapperTypeMatchingAllWrappingsOf` - subscribing to, filtering by, or ignoring an inner tevent type means matching every `IPublisherIdentifyingTevent<TTevent>` of it.
- Added `PublisherIdentifyingTevent.Wrapped`: the normalization a boundary uses when it receives a tevent that may or may not already be wrapped - an already-wrapped tevent passes through, anything else is auto-wrapped.
- `PublisherIdentifyingTevent<>`, `TaggregateIdentifyingTevent<>`, and `ITaggregateIdentifyingTevent<>` have type-identifier mappings, so closed wrapper types can be persisted and transmitted by `TypeId`.

## 0.3.2-alpha

- Fixed packaging: the `Taggregates\_docs` markdown files were packed into the NuGet package as contentFiles, so installing the package injected linked `Taggregates\_docs\*.md` items into consuming projects. They no longer ship in the package.

## 0.3.1-alpha

- Dispatcher configuration is now immutable and supplied at creation: `IMutableTeventDispatcher.New` takes a `TeventDispatcherConfig` (option flags plus tevent types ignored when unhandled), replacing the mutating `IgnoreUnhandled`/`IgnoreAllUnhandled` registration methods.
- Renamed `ITeventHandlerRegistrar` to `ITeventSubscriber`: the object through which a party subscribes handlers to a dispatcher's tevents.
- `ITeventSubscriber` is now `IDisposable`: disposing a subscriber removes every subscription made through it from the dispatcher. Disposing twice is harmless; registering through a disposed subscriber throws.
